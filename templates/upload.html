Every store's products are kept separate.

The file you upload only affects the store you pick above — it can't see or touch another store's products. Re-uploading the same SKU for that same store updates that product instead of duplicating it; the same SKU uploaded to a different store creates a separate product, since two stores are allowed to reuse a SKU for different things.

Re-uploading the same SKU updates that product instead of duplicating it.

A column left out of the file entirely is untouched on existing products (e.g. re-uploading just sku,title,price to bump prices won't clear anyone's images or category). A column that's present but blank for a row clears that field. The aspects/color columns are the one exception - new values are merged into whatever specifics a product already has, so they never get wiped out by a file that doesn't mention them.

Expected columns
ColumnRequiredNotes
skuYesYour own unique product code
titleYesListing title (trimmed to 80 characters)
priceYesNumber, e.g. 24.99
descriptionNoFalls back to title if left blank
quantityNoDefaults to 1
category_idNoeBay category ID — look this up in the Taxonomy API if unsure
brandNoUsed as the Brand aspect
conditionNoNEW, USED, etc. Defaults to NEW
image_urlNoOne or more public, direct image links. For multiple images, separate them with | (or a comma) in the same cell — up to 12, eBay's limit. Extra ones beyond 12 are dropped automatically.
colorNoShorthand for a single Color aspect (e.g. Black). Ignored if you already set Color in the aspects column below.
aspectsNo Any other category-specific details eBay's item specifics ask for (Size, Material, Department, etc.) — most categories require a few of these to publish.
Format: Key:Value|Key:Value, e.g. Size:Large|Material:Cotton. Multiple values for one key: Size:Large,XL.
Before publishing, the app checks the product's category against eBay's actual requirements and will tell you exactly which required specifics are still missing, if any.
